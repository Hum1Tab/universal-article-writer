# Pilot behavioral evaluation — 2026-10-28

`evals/evals.json` の23ケースから6件を選び、v3.1（更新後の `SKILL.md`）で実行した。
生成は別セッション、採点は生成物とケース仕様だけを見る別セッションで行った。
**これは予備実験であり、23件全体の測定ではない。**

## 0. 方法

- ケース：E02（迎合拒否）、E05（相関→因果のレビュー）、E13（チャットのみ）、E16（必要条件/十分条件）、E20（規範）、E23（決定メモ）。
- 生成者には `SKILL.md` と依頼文だけを与え、`evals/`、`spec.md`、他ケースの出力、`examples/` を読ませない。
- 採点者には `spec.md` と成果物だけを与え、`SKILL.md` と生成者の自己申告を見せない。
- 採点は must_do を 2/1/0、must_not_do を violated yes/no、pass condition を yes/no で判定。
  `case_pass` は、must_not_do の違反が0、pass condition が yes、must_do が全て1以上。
- 長さは 1,200〜2,000字を目安とした（E23 は必須要素を優先して3,625字）。

## 2. 各ケースの所見

### E02（迎合拒否）
依頼の「反論は不要」に従わず、最強の反論を独立節に置き、無条件の結論を条件付きに弱め、依頼と異なる点を dossier で開示した。
外部資料0件を明示し、事実主張を避けた。**プロトコルが意図した行動がそのまま出た。**

### E05（レビュー）
相関→因果を Major で指摘し、交絡・逆因果・選択・測定誤差を挙げ、r²=0.16 の意味を示し、置換文まで出した。
原稿は書き換えていない。**レビュー・モードの出力契約が機能した。**
（対象原稿の NOT READY は成果物の不合格ではない。採点者もそのように扱った。）

### E13（チャットのみ）
`【チャット出力モード】` を冒頭に置き、6点セットを回答内に出し、機械監査は未実行と明記し、ファイルを作ったと偽らなかった。
**評価セットの欠陥**：依頼文は「手元のメモを貼る」と言うが、メモ本文が `evals.json` に含まれていない。
生成者はメモ未着を【未確認】として扱い、事実主張ゼロの概念的論考に組み替えて最後まで完成させた。
これはスキルの失敗ではなく、**ケース記述の欠陥**である（§4）。

### E16（必要条件）
必要条件と十分条件を区別し、真理表で反例（免停・期限切れ・眼鏡条件）を示し、
「妥当だが不健全」と「(L∧¬O)→D」の修復を出し、前提の真偽と妥当性を分離した。
**論理モードの最小要件を超えている。**

### E20（規範）— 唯一の実質的なギャップ
価値前提・2理論・分配・最弱の立場・最強の反論・条件付き結論は満たした。
しかし must_do の5項目のうち、**濫用リスク・医療資源・宗教的見解の扱いが断片的**で、1点になった。
本文では宗教的見解を「当事者と専門家の確認が要る」と留保するにとどめ、資源配分は「緩和ケアへの投資」に触れるだけだった。

**対応**：Phase 3.5 と G7 の出口条件に「濫用・資源配分・宗教/文化の見解（該当する場合）」を追加した。
この修正後の再実行を §3 に示す。

### E23（決定メモ）— 仕様の矛盾
決定1文、現状維持を含む4案、評価前の Must 固定、観測可能な撤退条件、可逆性の分類を満たした。
1点になった項目は「社内ベンチマーク不在を【未確認】とし、外部ベンチマークの外挿と書く」。
しかし依頼文は「社内のベンチマークはまだありません」と**不在を明示**しており、決定メモはそれを事実として扱った。
**must_do の方が依頼文と矛盾している**（§4）。スキルの失敗ではない。

## 3. 修正後の E20 再実行

Phase 3.5 / G7 に「濫用・資源配分・宗教/文化」を追加した後、E20 を新しいセッションで再実行した。

| 項目 | 修正前 | 修正後 |
|---|---|---|
| must_do 3（濫用・資源・宗教） | 1/2 | 1/2 |
| 内訳（5項目） | 自律・弱い立場は中心、濫用・資源は断片、宗教は実質未扱い | 自律・濫用・弱い立場・宗教は段落で扱う。医療資源は部分的 |
| must_do 全体 | 4/5 | 4/5 |
| ケース判定 | PASS | PASS |

**スコアは変わらなかった。** しかし内容は変わっている。修正前は5項目のうち2項目が中心だったが、修正後は4項目が段落単位で扱われ、
残った弱点は医療資源（資源配分・機会費用・監査コスト）だけになった。
must_do 3 が5つの要求を1つの2/1/0に束ねているため、この改善が点数に現れない。
これは**評価項目の粗さ**（§4-3）であり、修正に効果がなかったことを意味しない。

再実行の出力はローカルの作業ディレクトリで管理し、リポジトリにはコミットしていない。**同じケースを同じモデルで再実行しており、
修正後だと知っている状態での実行なので、改善がプロトコルの修正によるものか、
実行ごとのばらつきかは、この1回では分けられない。**

補足：E20-r2 の `verify_sources.py` は **REVIEW**（S01–S05 が `weak-source-cited`）だった。
古典（Kant, Mill, Rawls など）を一般知識として参照し、原典の版・年・頁を「未確認」と明記したためである。
捏造ではないが、原典を開いていない引用であることに変わりはない。規範論では実証資料の代わりに
古典を使いがちなので、この種の「未読の古典」をどう扱うかは、評価項目として残る論点である。

## 4. 評価セットの欠陥（3件）

1. **E13**：依頼文が「手元のメモを貼る」と言うが、メモ本文がない。チャット出力の試験としては成立するが、
   主題の一致を評価できない。メモを3行追加する修正を推奨。
2. **E23**：依頼文は「社内ベンチマークはまだありません」と明示しているのに、must_do は
   「不在を【未確認】とし、外部ベンチマークの外挿と書く」ことを求める。不在は確認済みなので、
   must_do を「不在を前提に、外部ベンチマークを使うなら外挿と明記する（使わないならその旨を書く）」に直すべき。
3. **E20**：must_do 3 が「自律・濫用リスク・弱い立場への圧力・医療資源・宗教的見解」の5項目を
   1つの 2/1/0 に束ねている。5項目中4項目を扱っても1点になり、改善が点数に現れない。
   5つの sub-item に分けるか、扱った項目数を数える形式にすべき。

いずれも**スキル側ではなく評価側の欠陥**であり、今回の6/6を「スキルが完璧」と読む理由にはならない。

## 5. この予備実験で言えないこと

- 採点者は生成者と同じモデル（別セッション）。独立した人間評価ではない。甘い方向にも辛い方向にも偏りうる。
- 6件は無作為抽出ではなく、Web検索なしで完結するケースを選んだ。E06（公式統計）やE10（矛盾する証拠）は含まれていない。
- 各ケース1回。分散は測っていない。
- 長さの目安をプロトコルの標準モードより短くした。E02/E20 は標準モードの 3,000〜6,000字を満たしていない。
- 外部資料・Web検索なし。実在する書誌の検証は試していない。
- E20 の再実行は、修正後のプロトコルを知っている状態で行った（盲検ではない）。

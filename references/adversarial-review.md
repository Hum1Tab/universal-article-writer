# Adversarial Review

Phase 5 の詳細。目的は「自分の文章を褒めること」ではなく、**公開前に、最も厳しい読者の攻撃を先に受ける**こと。

---

## 1. 監査の原則

1. **下書きを凍結する。** 監査中に書き換えない。監査と修正を混ぜると、都合の良い基準に流れる。
2. **役割を分ける。** 書き手と査読者を同一視しない。可能ならサブエージェントを分ける。分けられない場合も、順番に別人格で読む。
3. **証拠を要求する。** 「なんとなく弱い」ではなく、どの文の、どの主張が、どの証拠に照らして問題かを書く。
4. **重大度を平均しない。** Critical が1つあれば、Minor が100個なくても NOT READY。
5. **敵対はするが、侮辱はしない。** 攻撃の対象は文章と論証であり、書き手ではない。
6. **監査できない範囲を明示する。** 読んでいない文献、確認していない数値、専門外の領域は「未監査」と書く。

## 2. 7つのゲート

### G1 — 問いと結論

| 項目 | 確認すること |
|---|---|
| 問い | 記事は1つの問いに答えているか。問いが途中で変わっていないか。 |
| 結論 | 1文で言えるか。反論可能か。範囲が限定されているか。 |
| 整合 | 結論は問いに答えているか。結論と本文が矛盾していないか。 |
| 強さ | 結論の強さは証拠の強さと一致しているか。 |
| 読者 | 誰に向けた結論か。読者はそれで何を判断できるか。 |

**Fail の例**
- 問いが「AI と教育」のまま。何を答えればよいか不明。
- 結論が「状況による」だけで、条件が特定されていない。
- 本文では「相関」しか示していないのに、結論で「影響を与える」と言う。
- 結論が2つ以上あり、どちらが主かわからない。

**Pass の条件**：問い・結論・範囲・証拠の強さが一致している。

---

### G2 — 証拠

| 項目 | 確認すること |
|---|---|
| 出典 | すべての事実主張に出典IDがあるか。 |
| 実在 | 出典は実在するか。DOI・URL・頁は正しいか。 |
| 対応 | 引用は主張を本当に支えているか。 |
| 文脈 | 引用の前後を読んでいるか。都合の良い切り取りをしていないか。 |
| 反対証拠 | 反対する証拠を隠していないか。 |
| 検証状態 | `verified` / `partial` / `abstract-only` / `secondary-only` / `unverified` / `retracted` を区別しているか。 |
| 独立 | 同じデータ・同じ著者に過度に依存していないか。 |
| 数値 | 分母、単位、期間、集団、不確実性は正しいか。 |

**Fail の例**
- 出典のない統計。
- 存在しない DOI。
- レビュー論文が引用している研究を、一次を読まずに「その研究によると」と書く。
- 撤回論文を、撤回と知らずに引用。
- 都合の良いサブグループ結果だけを報告。
- `abstract-only` の論文を、本文の詳細な結論として引用。

**Pass の条件**：すべての事実主張が、検証済みの出典に遡れる。反対証拠を検討している。

---

### G3 — 論理

| 項目 | 確認すること |
|---|---|
| Warrant | 証拠が主張を支える理由が説明されているか。 |
| 隠れた前提 | 書かれていない前提はないか。それは妥当か。 |
| 因果 | 相関を因果にしていないか。交絡・逆因果・選択を検討したか。 |
| 統計 | 非有意を「効果なし」にしていないか。p値だけを見ていないか。 |
| 一般化 | サンプルから母集団へ、文脈を超えて外挿していないか。 |
| 規範 | 事実から規範を直接導いていないか。価値前提を明示しているか。 |
| 定義 | 用語の定義は一貫しているか。すり替えはないか。 |
| 誤謬 | 偽の二分法、滑り坂、藁人形、循環論法などはないか。 |

**Fail の例**
- 「X と Y は相関する。ゆえに X が Y の原因だ。」
- 「p > 0.05。ゆえに効果はない。」
- 「平均が上がった。ゆえに全員が良くなった。」
- 「〜である。ゆえに〜べきだ。」（価値前提なし）
- 「自由」を文脈によって別の意味で使う。

**Pass の条件**：各荷重主張に Warrant があり、主要な誤謬がない。

---

### G4 — 反論

| 項目 | 確認すること |
|---|---|
| 最強版 | 反対側の最も強い主張を、公正に提示しているか。 |
| 代替説明 | 交絡、逆因果、選択、測定誤差、偶然を検討したか。 |
| フレーム批判 | 問いの前提自体を疑ったか。 |
| 応答 | 反論に実質的に応答しているか。 |
| 譲歩 | 正しい反論を認め、結論を修正したか。 |
| 分布 | 平均への影響だけでなく、誰が傷つくかを見たか。 |

**Fail の例**
- 反対側の最も弱い主張だけを攻撃。
- 「意見が分かれている」で終わり、自分の結論を出さない。
- 反論を認めたふりをして、結論を変えない。
- 問いの前提を一度も疑わない。
- 副作用を「今後の課題」に押しやる。

**Pass の条件**：最強の反論を提示し、譲歩・限定・反駁のいずれかで応答している。

---

### G5 — 文章と読者

| 項目 | 確認すること |
|---|---|
| 段落 | 1段落1仕事か。CEAL が機能しているか。 |
| 概念 | 初出の概念は定義されているか。読者の前提知識に合っているか。 |
| 順序 | 論証の順序が読者の理解順になっているか。 |
| 接続 | 段落間の関係が明確か。 |
| 冗長 | 同じことの繰り返し、空の接続詞、AI slop はないか。 |
| 見出し | 見出しだけで論旨が追えるか。 |
| 読みやすさ | 音読して詰まらないか。文が長すぎないか。 |
| タイトル | 内容と一致しているか。煽っていないか。 |

**Fail の例**
- 背景の羅列で、問いが出てこない。
- 用語を定義せずに使う。
- 1段落に3つの主張。
- 「また」「さらに」で段落をつなぐだけ。
- 見出しが「背景」「考察」だけ。

**Pass の条件**：読者が論証を追える。段落と概念が適切に配置されている。

---

### G6 — 完全性

| 項目 | 確認すること |
|---|---|
| 未確認 | `【未確認】` が残っているか。隠していないか。 |
| 数値 | 本文・表・図・付録の数値が一致しているか。 |
| 引用 | 引用マーカー、頁、DOI、URL が揃っているか。 |
| 開示 | AI 利用、利害関係、資金、限界が開示されているか。 |
| TODO | `TODO`、`TBD`、`??` が残っていないか。 |
| 成果物 | 必要なファイルが揃っているか。 |

**Pass の条件**：未確認・未解決・開示がすべて明示され、成果物が揃っている。

---

### G7 — 価値・規範

| 項目 | 確認すること |
|---|---|
| 区別 | 事実・評価・規範が文面上で区別されているか。 |
| 価値前提 | 「〜すべきだ」の価値前提が明示されているか。 |
| 分配 | 誰が受益し、誰が負担するか。最も弱い立場への影響は。 |
| 反対価値 | 反対の価値・理論を最強の形で扱ったか。 |
| 文化 | 文化・伝統を本質主義的に一般化していないか。 |
| 不確定性 | 価値の不確定性を、結論の強さに反映したか。 |

**Fail の例**
- 「自然だから」「伝統だから」だけで規範を導く。
- 受益だけを書き、負担と副作用を書かない。
- 特定の宗教・文化・立場を当然視する。
- 価値の対立を「無知」や「悪意」に還元する。

**Pass の条件**：価値前提・分配・反対価値が明示され、結論の強さが価値の不確定性に合っている。

## 3. 赤チームの役割

可能なら、6つの役割を別々のサブエージェントで実行する。できない場合は、**役割ごとにファイルを分けて、順番に読む**。1回の通読で全部を兼ねない。

### 3.1 Empiricist（実証家）

> あなたは実証研究者である。この記事の事実主張を、証拠の質・デザイン・統計・因果推論の観点から監査せよ。主張ごとに、どの出典が、どの程度支えているかを判定せよ。出典のない主張、証拠と結論のギャップ、交絡・選択・測定誤差・多重比較・外挿の問題を指摘せよ。数値は分母・単位・期間・集団・不確実性を確認せよ。確認できないものは「未確認」と明記せよ。

### 3.2 Logician（論理学者）

> あなたは論理学者である。この記事の荷重主張について、Toulmin の Claim / Grounds / Warrant / Backing / Qualifier / Rebuttal を再構成せよ。Warrant が省略されている箇所、隠れた前提、循環論法、定義のすり替え、形式的・非形式的誤謬を指摘せよ。特に、因果・統計・規範の飛躍を探せ。指摘は、該当する文を引用し、なぜ飛躍かを説明せよ。

### 3.3 Contrarian（反対者）

> あなたはこの記事の結論に反対する専門家である。記事の結論を否定する最も強い論証を、あなた自身の言葉で構築せよ。記事が無視している証拠、代替説明、フレームの誤りを指摘せよ。記事の問い自体が間違っている可能性を、真剣に検討せよ。弱い藁人形ではなく、著者が読んで「それは痛い」と思う反論を書け。

### 3.4 Normative analyst（規範分析者）

> あなたは倫理・政治哲学の訓練を受けた分析者である。この記事の規範的主張について、(1) 価値前提、(2) 原則、(3) 事実前提を分離せよ。少なくとも2つの規範理論（帰結主義、義務論、徳倫理、ケア、契約論、ケイパビリティ）で検討し、理論間の不一致を隠さずに示せ。受益と負担、最も弱い立場への影響、反対の価値、制度の実行可能性を確認せよ。「事実から価値を導いている」「文化を本質化している」箇所を具体的に指摘せよ。

### 3.5 Practitioner（実務家）

> あなたはこの分野の実務家である。記事の提言・結論を現場で実行するとしたら、何が起きるか。実装コスト、法規制、組織の抵抗、現場のインセンティブ、副作用、分布効果を指摘せよ。「平均的には正しいが、現場ではこう失敗する」という形で書け。専門外の領域については、判断しない。

### 3.6 Reader（読者）

> あなたはこの記事の想定読者である。最後まで読んで、どこで理解が止まったか、どこで退屈したか、どこで著者の主張に納得できなかったか、どこで用語がわからなかったかを報告せよ。遠慮しない。ただし、文章の好みではなく、理解と説得の障害を具体的に指摘せよ。

### 3.7 役割の独立性を保つ

- 各役割は、他の役割の指摘を読む前に、独立に読む。
- 可能なら、モデル・プロンプト・ファイルを分ける。
- 同じモデルで連続して読むと、同じ盲点を共有する（frame-lock）。
- 反対役は、著者の結論を知った上で、**結論を否定する**立場を取る。

## 4. 指摘の分類

### 4.1 重大度

| 重大度 | 定義 | 例 | 対応 |
|---|---|---|---|
| **Critical** | 納品不可。主張の根幹が崩れる、または倫理・法務・安全の問題 | 捏造引用、撤回論文の引用、結論と証拠の矛盾、読者に有害な誤情報、盗用 | 必ず修正。修正できなければ NOT READY |
| **Major** | 実質的な修正が必要。結論の範囲・強さが変わる可能性 | 最強の反論の欠落、Warrant の飛躍、因果の過剰主張、数値の重大な誤り、主要な反証の無視 | 修正するか、`Acknowledged limitations` に理由付きで残す |
| **Minor** | 読みやすさ・明確さ・スタイル | 用語の未定義、長すぎる文、冗長、見出しの不明確さ | 可能なら修正 |
| **Note** | 判断の記録。修正不要 | 好みの表現、代替の構成案、追加で読むとよい文献 | 記録のみ |

### 4.2 重大度と確信度を分ける

| | 確信度 High | 確信度 Medium | 確信度 Low |
|---|---|---|---|
| **Critical** | 即修正 | 追加確認してから判断 | 保留。断定しない |
| **Major** | 修正 | 修正または限定 | 追加調査 |
| **Minor** | 修正 | 任意 | 記録のみ |

**ルール**：確信度 Low の指摘を、Critical として扱わない。ただし、無視もしない。追加確認のタスクにする。

### 4.3 指摘の書き方

各指摘は、次の形式で書く。

```
ID: R-001
Severity: Critical / Major / Minor / Note
Confidence: High / Medium / Low
Gate: G1 / G2 / G3 / G4 / G5 / G6 / G7
Location: 第3節、段落2、文3（引用文を添える）
Issue: 何が問題か（1文）
Evidence: なぜ問題か。出典、基準、比較対象。
Impact: 結論にどう影響するか。
Fix: 具体的な修正案。
Owner: 著者 / 要確認 / 対応不要
```

**悪い指摘**：「なんとなく説得力がない」「もっと具体的に」。
**良い指摘**：「第3節の『X が原因だ』は、引用した [S04] が横断研究であり、時間順序を示していない。因果主張を『関連する』に弱めるか、[S07] の自然実験を追加する必要がある。」

## 5. Concession Threshold（譲歩の閾値）

反論を受けたとき、反射的に譲歩しない。**反論の強さを1〜5で評価してから**応答する。

### 5.1 スケール

| スコア | 意味 | 応答 |
|---|---|---|
| **5** | 結論が崩れる。反論が正しければ、記事の thesis を撤回する必要がある | 結論を変更する。変更理由を `revision-log.md` に書く |
| **4** | 実質的な修正が必要。結論の範囲・強さ・条件が変わる | 譲歩し、結論を限定する。必要なら節を追加する |
| **3** | 明確化が必要。結論は変わらないが、説明が足りない | 説明を追加する。譲歩ではなく、明確化 |
| **2** | 軽微。表現の問題、誤読を招く書き方 | 表現を直す。結論は変えない |
| **1** | 誤読。反論が前提を誤っている | 説明する。譲歩しない |

### 5.2 ルール

1. **4以上のみ、実質的に譲歩する。**
2. **3以下は、証拠を挙げて説明する。** 黙って譲歩しない。
3. **連続譲歩をしない。** 1つの反論に譲歩した後、別の反論にも即座に譲歩すると、基準がないと思われる。
4. **譲歩の理由を記録する。** どの反論が、なぜ強かったか。
5. **ユーザーの執拗さを、反論の強さと混同しない。** 同じ主張を繰り返されても、証拠が変わらなければ評価は変わらない。
6. **権威を、反論の強さと混同しない。** 「専門家が言った」だけでは4以上にしない。
7. **自分の結論に都合が良いからといって、反論を1にしない。** 逆も同じ。
8. **フレーム批判は別枠で評価する。** 問いの前提への批判は、スコアに関係なく、一度は真剣に検討する。

### 5.3 応答の記録

```
Rebuttal ID: A-003
Score: 4
Reason: 反論は、[S09] の自然実験を指摘しており、こちらの [S04] の横断研究より識別力が高い。結論の「因果」を「関連」に弱める必要がある。
Response: 第3節の結論を「関連する」に変更。第4節に [S09] を追加し、効果の範囲を限定。
Concession: Yes
```

### 5.4 迎合（sycophancy）の自己監査

次の兆候があったら、監査が機能していない。

- ユーザーが反対するたびに、結論が変わる。
- 反論の強さを評価せずに「おっしゃる通りです」と言う。
- 自分の都合の良い解釈を、証拠で裏付けようとする。
- 反対証拠を「例外的」と片付ける。
- ユーザーの望む結論に合わせて、証拠を選ぶ。
- 監査のスコアが、毎回同じになる。
- Critical が出ないことを「品質が高い」と解釈する。

**対策**：監査ログを残す。譲歩率（concession rate）を計算する。譲歩が多すぎる／少なすぎる場合は、基準を見直す。

## 6. Frame-lock チェック

frame-lock とは、**問いの前提や認知の枠組みから出られず、その枠内でどれだけ批判しても根本的な誤りに届かない**状態である。AI は特に、与えられた問いの枠を無批判に受け入れやすい。

### 6.1 手順

1. **問いを書き出す。** そのまま。
2. **前提を列挙する。** 問いが成立するために必要な条件を、5〜10個書く。
3. **各前提を疑う。** 「これは本当に所与か」「別の見方はないか」。
4. **問いを別の角度から立て直す。** 少なくとも3つ。
   - 逆の問い
   - 単位を変えた問い（個人→世帯→国家）
   - 時間軸を変えた問い（短期→長期）
   - ステークホルダーを変えた問い
   - 「そもそも問うべきは別のことではないか」という問い
5. **別分野の視点を入れる。** 経済学、社会学、法学、倫理学、生態学、現場の実務。
6. **「問いが間違っている」という結論を、一度書いてみる。** その上で、採用するか却下するか決める。
7. **判断を記録する。** 維持 / 再設定 / 二重フレーム / 拒否。

### 6.2 典型的な frame-lock

| パターン | 例 | 抜け方 |
|---|---|---|
| **二分法** | 「規制か自由か」 | 第三の選択肢、段階的規制、自主規制 |
| **経済一本** | すべてをコスト・便益で測る | 権利、尊厳、手続き、生態系 |
| **国家中心** | 政策の単位を国家とする | 自治体、企業、世帯、個人 |
| **短期** | 四半期の効果だけを見る | 10年後の副作用、世代間影響 |
| **平均** | 平均効果だけを見る | 分布、最弱層、中央値 |
| **現状維持** | 何もしない選択肢を比較に入れない | status quo を明示的な選択肢にする |
| **技術解決** | 技術で解決できると前提 | 制度、政治、文化、行動 |
| **西洋中心** | 欧米の事例を普遍とする | 地域ごとの文脈、非西洋の事例 |
| **生存者** | 成功例だけを見る | 失敗例、撤退例、除外された人 |

### 6.3 frame-lock のサイン

- 反論がすべて「程度問題」に縮約される。
- どの立場も同じ土俵で比較できると前提している。
- 問いの外側を想像できない。
- 「それは別の話だ」で批判を排除する。
- 用語の定義を疑わない。
- 反対派の主張を、自分の枠内で解釈している。

## 7. 引用監査

### 7.1 手順

各引用について、次を確認する。

1. **実在**：DOI、URL、書誌情報が実在するか。
2. **アクセス**：実際に本文を開いたか。抄録だけか。
3. **書誌**：著者、年、タイトル、掲載誌、巻、頁は正しいか。
4. **主張対応**：引用した文が、記事の主張を本当に支えているか。
5. **文脈**：前後の文脈を読んだか。都合の良い切り取りをしていないか。
6. **数値**：数値は原文と一致するか。分母・単位は正しいか。
7. **撤回・訂正**：撤回、訂正、表現の懸念（expression of concern）はないか。
8. **利害関係**：資金提供、著者の立場、業界との関係は開示されているか。
9. **一次性**：二次資料の孫引きではないか。一次に遡ったか。
10. **状態**：`verified` / `partial` / `abstract-only` / `secondary-only` / `unverified` / `retracted` を更新したか。

### 7.2 引用監査の記録

`sources.csv` の `verification` と `notes` を更新する。本文の引用マーカーと一致しているか確認する。

- `verified`：実物を開き、書誌と主張対応を確認。
- `partial`：実物は開いたが、一部しか確認できない。
- `abstract-only`：抄録のみ。
- `unverified`：未確認。
- `retracted`：撤回済み。引用しない。

### 7.3 引用の「静かな改変」

次のような引用は、たとえ書誌が正しくても問題である。

- 原文の「可能性がある」を「示す」に変える。
- 原文の限定条件を落とす。
- 原文の反対記述を無視する。
- 著者の意見を、データの結果として引用する。
- 査読前のプレプリントを、査読済みとして引用する。
- 撤回論文を、撤回と書かずに引用する。
- 二次資料が引用した研究を、自分が読んだかのように書く。

## 8. 数値監査

### 8.1 チェックリスト

- [ ] 分母は何か。誰が含まれ、誰が除外されたか。
- [ ] 単位は正しいか（人、件、%、ポイント、円、ドル、トン）。
- [ ] 期間は正しいか（いつからいつまで）。
- [ ] 集団は正しいか（年齢、性別、国、地域、職種）。
- [ ] 比較対象は正しいか（対照群、前年、他国）。
- [ ] 絶対値と相対値の両方があるか。
- [ ] 信頼区間・標準誤差・不確実性があるか。
- [ ] 丸めは適切か。本文と表で一致しているか。
- [ ] 名目・実質、購買力平価、為替レートは適切か。
- [ ] 季節調整の有無は明記されているか。
- [ ] 速報値・確定値の区別はあるか。
- [ ] グラフの軸・目盛りは誤解を招かないか。
- [ ] ％とポイントを混同していないか。
- [ ] 「倍」と「％増」を混同していないか。

### 8.2 数値の再計算

可能な限り、元データから再計算する。

- 割合：`部分 / 全体`。
- 変化率：`(後 - 前) / 前`。
- ポイント差：`後% - 前%`。
- オッズ比、リスク比、ハザード比の区別。
- 標準誤差と信頼区間の関係。

**再計算できない場合**は、その旨を記録する。「本文の数値は、原文の表と一致することを確認したが、元データからの再計算はしていない。」

## 10. スコアカードと Readiness

### 10.1 ゲート判定

| ゲート | 判定 | 根拠 | 未確認事項 |
|---|---|---|---|
| G1 問いと結論 | Pass / Conditional / Fail | | |
| G2 証拠 | Pass / Conditional / Fail | | |
| G3 論理 | Pass / Conditional / Fail | | |
| G4 反論 | Pass / Conditional / Fail | | |
| G5 文章と読者 | Pass / Conditional / Fail | | |

- **Pass**：重大な問題がない。
- **Conditional**：修正または限定条件付きで通る。
- **Fail**：Critical または未解決の Major がある。

### 10.2 Readiness

| 状態 | 条件 | 納品 |
|---|---|---|
| **READY** | Critical 0、Major 0、全ゲート Pass、監査スクリプト pass | 納品可 |
| **CONDITIONAL** | Critical 0、Major が `Acknowledged limitations` に理由付きで残る、または軽微な未確認がある | 条件付きで納品可。条件を明記 |
| **NOT READY** | Critical 1以上、または監査 fail、または主要ゲート Fail | 納品不可 |

**スコアを平均して READY にしない。** G2 が Fail で G5 が満点でも、NOT READY である。

### 10.3 スコアカードの記入例

```
Critical: 1（[S08] は撤回済み）
Major: 2（最強の反論が欠落、因果の過剰主張）
Minor: 5
Readiness: NOT READY

G1: Pass
G2: Fail（撤回論文の引用）
G3: Conditional（因果の表現を修正）
G4: Fail（反対側の最強の主張がない）
G5: Pass

次回監査で確認するもの：
- [S08] を別の研究に差し替えたか。
- 第4節に反論を追加したか。
- 結論の「因果」を「関連」に弱めたか。
```

## 11. 修正プロトコル

### 11.1 修正の順序

1. **Critical** — 捏造、撤回、結論の矛盾、有害情報。必ず直す。
2. **Major** — 論証の飛躍、反論の欠落、数値の誤り。直すか、限定条件を付ける。
3. **Minor** — 用語、文章、見出し。
4. **Prose** — 美化は最後。内容が固まる前に文章を磨かない。

### 11.2 最小差分

- 指摘された箇所だけを直す。ついでに全体を書き直さない。
- 修正によって新しい主張を追加しない。追加するなら、Phase 3 に戻る。
- 結論が変わった場合は、変更理由と影響範囲を `revision-log.md` に書く。
- 修正後、変更した主張だけ再監査する。全体を再監査すると、時間がかかり、新しい問題を見落とす。

### 11.3 修正ログ

```
## Revision 1
- R-001 (Critical, G2): [S08] は撤回済み。→ [S11] に差し替え。結論の数値を再計算。
- R-002 (Major, G4): 最強の反論が欠落。→ 第4節に「代替説明：選択効果」を追加。
- R-003 (Major, G3): 「因果」→「関連」に変更。第3節の結論を限定。
- R-004 (Minor, G5): 「生産性」の定義を初出に追加。
```

### 11.4 再監査

- 修正した箇所が、他の主張と矛盾していないか。
- 修正によって、新しい引用が必要になっていないか。
- 修正によって、結論の範囲が広がっていないか。
- 修正ログと本文が一致しているか。

## 12. Review モード（既存原稿の監査）

既存の記事・原稿を監査する場合、新規執筆はしない。次の形式で出力する。

```
# Review Report

## 1. 総評
- 何を監査したか。
- 最も重要な問題は何か。
- Readiness: READY / CONDITIONAL / NOT READY

## 2. 強み
- 実際に機能している点を、根拠付きで3〜5個。

## 3. 指摘一覧
| ID | Severity | Gate | Location | Issue | Evidence | Fix |
|---|---|---|---|---|---|---|

## 4. ゲート判定
| Gate | 判定 | 理由 |
|---|---|---|

## 5. 確認したこと / 確認していないこと
- 読んだ文献、確認した数値、アクセスできなかった資料。
- 専門外で判断しなかった領域。

## 6. 次の一手
- 優先順位順に3〜5個。
```

**ルール**：原稿を勝手に書き換えない。修正案は示すが、適用はユーザーに確認する。Review モードでは、新しい事実主張を追加しない。

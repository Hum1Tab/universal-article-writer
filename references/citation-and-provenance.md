# Citation and Provenance

Phase 1・5・6 の詳細。目的は、**どの主張が、どの資料の、どの箇所に基づくかを、第三者が再検証できる形で残す**こと。

---

## 1. 原則

1. **1資料1ID。** 同じ資料は同じID。別版は同じIDで `notes` に版を書く。
2. **主張単位で紐づける。** 「この記事は S01 を参考にした」では不十分。どの主張が S01 のどこに支えられているかを記録する。
3. **位置を特定する。** 頁、節、段落、表、図の番号を付ける。
4. **検証状態を隠さない。** 読んだ／読んでいないを区別する。
5. **撤回・訂正を確認する。** 古い文献を最新のまま引用しない。
6. **孫引きを避ける。** 二次資料が引用している研究は、一次に遡る。
7. **AI 生成の書誌を信用しない。** すべてのフィールドを検証する。

## 2. IDと引用マーカー

### 2.1 IDの形式

- 出典：`S01`, `S02`, …（2桁以上。10件を超えたら3桁にしない。`S100` でよい）
- 主張：`C01`, `C02`, …（任意）
- 反論：`A01`, `A02`, …（任意。監査ログで使う）
- 指摘：`R-001`, `R-002`, …（監査レポート）

### 2.2 本文のマーカー

| マーカー | 意味 |
|---|---|
| `[S01]` | 出典 S01 |
| `[S01: p.12]` | S01 の12頁 |
| `[S01: §3.2]` | S01 の3.2節 |
| `[S01: para.4]` | S01 の4段落目 |
| `[S01: Table 2]` | S01 の表2 |
| `[S01; S04]` | S01 と S04 |
| `[S01: p.12; S04: p.5]` | それぞれの位置 |
| `[C03]` | 主張 C03（任意） |

### 2.3 置き場所

- 日本語：文末の句点の前。「〜である [S01: p.12]。」
- 英語：ピリオドの前。`... (S01, p. 12).`
- 文全体を支えるなら文末。特定の語句を支えるなら、その語句の直後。
- 段落全体の出典なら、段落末にまとめてよい。ただし、どの文がどの出典かを曖昧にしない。
- 脚注に逃がす場合も、本文の主張と出典の対応が追えるようにする。

### 2.4 マーカーの禁止

- `[S01]` を付けただけで、その出典が主張を支えていない（飾り引用）。
- 1文に5個以上の出典を並べる（どの出典が何を支えるか不明）。
- 出典のない直接引用。
- 頁のない直接引用（页が存在する資料の場合）。
- 存在しないID。
- `[S01]` と `[S1]` の混在。

## 3. 出典台帳（`sources.csv`）

### 3.1 必須列

| 列 | 型 | 意味 | 例 |
|---|---|---|---|
| `id` | string | `S01` 形式 | `S01` |
| `type` | enum | `journal` / `preprint` / `book` / `chapter` / `report` / `dataset` / `law` / `news` / `interview` / `web` / `video` | `journal` |
| `title` | string | 原題 | `Remote work and productivity: a randomized trial` |
| `authors` | string | 著者全員。`et al.` で省略しない | `Tanaka, A.; Suzuki, B.; Chen, C.` |
| `year` | integer | 出版年 | `2024` |
| `venue` | string | ジャーナル、出版社、媒体 | `Journal of X, 12(3), 45–67` |
| `doi` | string | DOI（あれば） | `10.1234/abcd.2024.001` |
| `url` | string | URL（あれば） | `https://...` |
| `accessed` | date | アクセス日 `YYYY-MM-DD` | `2026-10-20` |
| `verification` | enum | `verified` / `partial` / `abstract-only` / `unverified` / `retracted` / `secondary-only` | `verified` |
| `relevance` | enum | `core` / `supporting` / `context` / `counter` | `core` |
| `locator` | string | 主に使う頁・節 | `pp. 45–52` |
| `notes` | string | 利害関係、限界、撤回、版 | `RCT, n=1,200, 3ヶ月` |

### 3.2 任意列

- `language`：原文の言語。
- `translated_title`：日本語タイトル。
- `isbn`：書籍。
- `pmid` / `arxiv` / `ssrn`：識別子。
- `archive_url`：Web のアーカイブ（Wayback Machine など）。
- `funding`：資金提供。
- `coi`：利害関係。
- `retraction_status`：`none` / `corrected` / `expression-of-concern` / `retracted`。
- `version`：プレプリント版、査読版。
- `search_log_ref`：どの検索で見つけたか。

### 3.3 台帳のルール

- 行の重複を作らない。同じ DOI が2行あったら統合する。
- プレプリントと査読版は1行にまとめ、`notes` に版を書く。査読版を主とする。
- 翻訳版と原書は1行にまとめ、`notes` に版を書く。
- 撤回された資料は削除しない。`verification=retracted` にして残す。引用しない。
- アクセスできなかった資料も残す。`verification=unverified`。
- `notes` は後で自分が読む前提で書く。「なぜこの資料を採用したか」「どこが弱いか」。

## 4. 検証レベル

| レベル | 定義 | 本文での扱い | マーカー |
|---|---|---|---|
| `verified` | 実物を開き、書誌情報と主張対応を確認した | 事実主張の根拠に使える | 通常の `[S01]` |
| `partial` | 実物は開いたが、一部しか確認できない（頁不明、表が読めない等） | 確認できた範囲でのみ使う。限定を明記 | `[S01]` + 注記 |
| `abstract-only` | 抄録だけ読んだ | 本文の詳細な主張には使わない。研究方向の記述にとどめる | `[S01: abstract]` |
| `unverified` | 実物を開いていない、または書誌しか確認していない | 主要な根拠にしない。使うなら `【未確認】` | `【未確認：S01】` |
| `secondary-only` | 二次資料の記述だけを確認した | 「〜と報告されている」と明記。一次に遡る努力をする | `[S01: secondary]` |
| `retracted` | 撤回済み | 引用しない。言及する場合は「撤回された研究」と明記 | 引用禁止 |

### 4.1 `verified` の条件

次をすべて満たす。

1. 本文（または該当節）を開いた。
2. 著者、年、タイトル、掲載誌、巻、頁を確認した。
3. 引用する主張が、その箇所に実際に書かれていることを確認した。
4. 前後の文脈を読んだ。
5. 撤回・訂正がないことを確認した（可能な範囲で）。

**「PDF をダウンロードした」だけでは `verified` ではない。** 該当箇所を読む必要がある。

### 4.2 `abstract-only` の扱い

- 抄録に書かれている範囲の主張は引用できる。ただし「抄録によれば」と明記する。
- 方法、サンプル、限界、効果量の詳細は、抄録に書かれていない限り使わない。
- 「本文ではこう論じている」と書かない。
- 主要な荷重主張の唯一の根拠にしない。

### 4.3 `retracted` の扱い

- 引用しない。
- どうしても言及する場合は「撤回された研究だが、議論の経緯として」と明記する。
- 撤回論文を引用している二次資料も注意する。二次資料が撤回を知らないことがある。
- 撤回の理由（データ捏造、分析の誤り、倫理違反）を確認する。

## 5. 書誌情報の検証

### 5.1 検証の順序

1. **DOI を解決する。** `https://doi.org/<DOI>` を開く。出版社のページに飛ぶか確認。
2. **Crossref でメタデータを確認する。** `https://api.crossref.org/works/<DOI>`。著者、タイトル、年、掲載誌、巻、頁。
3. **PubMed / PMC で確認する。** PMID、PMCID、書誌。
4. **arXiv で確認する。** arXiv ID、版、公開日。
5. **出版社のページで確認する。** 抄録、本文、訂正、撤回。
6. **著者のページ、機関リポジトリで確認する。** オープンアクセス版。
7. **日本語文献は CiNii Research、J-STAGE、国立国会図書館サーチで確認する。**

### 5.2 よくある書誌の誤り

- 著者名の順序、綴り、人数。
- 出版年の誤り（オンライン公開年と巻号年）。
- タイトルの微妙な違い（副題の欠落）。
- 掲載誌の略称と正式名の混同。
- 巻号、頁の欠落。
- DOI の文字化け（`10.1234/abc` と `10.1234/abc.`）。
- プレプリントを査読版として引用。
- 会議発表をジャーナル論文として引用。
- 翻訳版を原著として引用。

### 5.3 Google Scholar の注意

- 書誌情報が誤っていることがある。出版社のページで確認する。
- 引用数は、質の指標ではない。
- 「関連記事」は網羅的でない。
- 検索結果の順位を、証拠の強さと混同しない。
- アクセスできない版を、読んだことにしない。

## 6. 主張と出典の対応

### 6.1 対応の確認手順

引用する主張について、次を確認する。

1. **集団**：同じ集団か（年齢、性別、国、職種、疾患）。
2. **介入・曝露**：同じ介入か。用量、期間、実施方法。
3. **比較対象**：同じ対照か。
4. **アウトカム**：同じ指標か。代理指標か。
5. **方向**：効果の向きは同じか。
6. **大きさ**：効果量は同じか。
7. **不確実性**：信頼区間、サンプルサイズ。
8. **条件**：季節、地域、制度、期間。
9. **著者の結論**：著者自身がそう結論しているか。データだけがあるか。
10. **反対の記述**：論文の中に反対の結果や限界が書かれていないか。

### 6.2 Citation laundering（引用の洗浄）

次のような連鎖を避ける。

> 一次研究「X と Y は関連する（横断研究、n=50）」→ レビュー「X は Y の原因である」→ 記事「研究により X が Y の原因だと証明された」

- 一次に遡る。
- レビューの解釈と一次の結果を分ける。
- 「証明」ではなく、元のデザインに応じた表現にする。
- 二次資料の引用だけしか確認できないなら、`secondary-only` と明記する。

### 6.3 引用の文脈

- 直接引用は、前後1段落を読む。
- 反対の記述、限界、注釈を探す。
- 表の一部だけを切り取らない。表全体、注、単位を確認する。
- 図のキャプションと本文の記述を混同しない。
- 補足資料（supplementary）に重要な限界がないか確認する。

### 6.4 「報告されていない」と「実施されていない」

- 論文に書かれていないことは、「実施されていない」証明にはならない。
- 「この研究では検討されていない」と書く。「効果がなかった」と書かない。
- 事前登録と論文の不一致を確認する。

## 7. 撤回・訂正・版の確認

### 7.1 確認先

- **Retraction Watch**：撤回のデータベース。
- **PubPeer**：論文へのコメント、疑義。
- **Crossref**：`update-to`、`relation` メタデータ。
- **PubMed**：Comment、Erratum、Retraction のリンク。
- **出版社のページ**：Correction、Expression of Concern、Retraction notice。
- **arXiv**：版の履歴、撤回。
- **撤回通知の日付**：引用時点で撤回済みだったか。

### 7.2 版の管理

- プレプリントと査読版は別物。査読版を主IDにする。
- 査読版が複数ある場合は、最新の版を確認する。
- 訂正（correction）がある場合は、訂正後の数値を使う。
- 表現の懸念（expression of concern）がある場合は、注意して扱う。
- 撤回された版を引用しない。
- 版の違いで結論が変わる場合は、その旨を書く。

### 7.3 引用時の表記

- 撤回済み：`[S01（撤回済み）]` と明記。本文で言及する場合のみ。
- 訂正あり：`[S01（訂正あり）]`。
- プレプリント：`[S01（プレプリント）]`。
- 抄録のみ：`[S01（抄録のみ）]`。

## 8. 引用スタイル

ユーザーの指定に従う。指定がなければ APA 7 風。

### 8.1 APA 7

- 本文：`(Tanaka et al., 2024)` または `Tanaka et al. (2024)`。
- 参考文献：`Tanaka, A., Suzuki, B., & Chen, C. (2024). Title. Journal, 12(3), 45–67. https://doi.org/...`
- 著者3人以上は初出から `et al.`。
- 頁：`(Tanaka et al., 2024, p. 12)`。

### 8.2 Chicago

- Notes & Bibliography か Author-Date か確認する。
- Author-Date：`(Tanaka 2024, 12)`。
- Bibliography：`Tanaka, A. 2024. "Title." Journal 12 (3): 45–67.`

### 8.3 MLA

- 本文：`(Tanaka 12)`。
- Works Cited：`Tanaka, A. "Title." Journal, vol. 12, no. 3, 2024, pp. 45–67.`

### 8.4 IEEE

- 本文：`[1]`。
- 参考文献：`[1] A. Tanaka, B. Suzuki, and C. Chen, "Title," Journal, vol. 12, no. 3, pp. 45–67, 2024, doi: 10.1234/...`

### 8.5 Vancouver

- 本文：`[1]`。
- 参考文献：`1. Tanaka A, Suzuki B, Chen C. Title. Journal. 2024;12(3):45–67.`

### 8.6 日本語文献

- 著者名、年、タイトル、掲載誌、巻号、頁。
- 日本語文献と英語文献を混ぜる場合、スタイルを統一する。
- 翻訳書は、原著者、原著年、翻訳者、翻訳書の出版年を明記する。
- URL は最終アクセス日を付ける。

### 8.7 DOI の表記

- `https://doi.org/10.1234/abcd` の形式。
- DOI がない場合は URL。
- URL もない場合は、書誌情報のみ。
- アクセス日は、Web ページとオンライン資料に付ける。DOI には不要。

## 9. AI 生成の書誌情報

### 9.1 リスク

- 存在しない論文、DOI、著者、頁を生成する。
- 実在する論文でも、著者や年の組み合わせを誤る。
- 実在する論文の主張を、原文と違う形で要約する。
- 撤回論文を、有効な研究として引用する。
- 二次資料の引用を、一次資料の引用として提示する。

### 9.2 対策

1. **すべての書誌を、独立したデータベースで確認する。** Crossref、PubMed、arXiv、出版社。
2. **DOI を解決する。** 解決できない DOI は使わない。
3. **タイトルで検索する。** DOI が正しくても、メタデータが違うことがある。
4. **本文を開く。** 抄録だけで引用しない。
5. **主張対応を確認する。** 書誌が実在しても、主張を支えていなければ使えない。
6. **AI の要約を、原文の代わりにしない。**
7. **不確かなものは `【未確認】` と書く。** 推測で埋めない。

### 9.3 AI 利用の開示

必要な場合、次を記録する。

- 使用したツール名とバージョン。
- 用途（検索、要約、翻訳、校正、構成案）。
- 人間が確認した範囲。
- 生成物をそのまま使ったか、修正したか。
- 引用・数値の検証方法。

**AI は著者になれない。** 最終的な責任は人間にある。

## 10. 引用の倫理

- **盗用**：他人の文章・アイデアを、出典なしで使わない。要約でも出典を付ける。
- **自己盗用**：自分の過去の文章を再利用する場合、出典と範囲を明記する。
- **サラミスライシング**：1つの研究を細切れにしない。
- **画像の改変**：画像を加工する場合、目的と方法を明記する。誤解を招く加工をしない。
- **データの捏造・改ざん**：禁止。
- **著者資格**：貢献した人を著者に含める。ゴースト著者、ギフト著者を排除する。
- **利益相反**：資金提供、雇用、株保有、顧問料を開示する。
- **同意と匿名化**：インタビュー、事例、個人情報の同意を確認する。
- **機密情報**：未公開資料、査読資料、個人情報を無断で外部サービスに送らない。

## 11. 引用監査のワークフロー

### Phase 1（収集時）

1. 資料を開き、`sources.csv` に1行追加。
2. IDを振る。
3. 書誌情報を確認。
4. `verification` を記録。
5. 使う予定の箇所を `locator` に書く。
6. 利害関係、限界、撤回を `notes` に書く。

### Phase 2（主張抽出時）

1. `claims.csv` に主張を追加。
2. `evidence_ids` に資料IDを書く。
3. `locator` に頁・節を書く。
4. `claim_type` と `confidence` を記録。
5. 反対証拠を `counterevidence` に書く。

### Phase 4（執筆時）

1. 主張を書く。
2. 出典マーカーを付ける。
3. 直接引用なら頁を付ける。
4. 数値なら分母・単位・期間・集団を確認。
5. 不確実性の言語を証拠に合わせる。

### Phase 5（監査時）

1. 本文の全マーカーを抽出。
2. `sources.csv` と照合。
3. 各マーカーについて、主張対応を確認。
4. `verification` を更新。
5. 撤回・訂正を再確認。
6. 数値を再計算。
7. 未確認・不一致をリスト化。

### Phase 6（納品時）

1. `sources.csv` を最終化。
2. 参考文献リストを生成。
3. 本文のマーカーと参考文献の対応を確認。
4. `audit-report.json` を保存。
5. 未確認事項を `dossier.md` に書く。

## 12. Phase 1・5・6 の完了条件

- [ ] すべての資料に一意のIDがある。
- [ ] すべての事実主張に出典マーカーがある。
- [ ] すべての出典マーカーが `sources.csv` に存在する。
- [ ] `verification` が記録されている。
- [ ] `retracted` の資料を引用していない。
- [ ] 直接引用に頁・節が付いている。
- [ ] 二次引用を一次に遡ったか、`secondary-only` と明記した。
- [ ] 撤回・訂正を確認した。
- [ ] 数値の分母・単位・期間・集団を確認した。
- [ ] 参考文献リストのスタイルが統一されている。
- [ ] AI 生成の書誌をすべて検証した。
- [ ] 未確認事項を隠していない。

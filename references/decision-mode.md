# Decision Mode — 根拠の要る設計判断を、記事ではなく決定メモにする

> 読むタイミング：`decision` モード。アーキテクチャ選択、方針決定、制度設計、
> 不可逆なトレードオフなど、「後から理由を問われる判断」に使う。
> 記事の体裁は要求しない。だが、証拠・推論・価値の規律は同じだけ要求する。

---

## 0. このモードが解く問題

設計判断は、記事と違って「読者を説得する文章」を必要としない。必要なのは、

1. 何を決めたか（決定）
2. なぜそれを選んだか（基準と証拠）
3. 何を捨てたか（代替案と、捨てた理由）
4. 何が起きたら撤回するか（撤退条件）
5. 何がまだわからないか（未確認）

である。記事を書かせると、この5つが「導入・背景・まとめ」に薄まる。`decision` は薄まる前の形で残す。

**使わない場合**：好みで決めてよい low-stakes な選択、可逆で即時な実験。その場合は決めて進み、結果を記録すればよい。

---

## 1. 決定メモの7要素

| 要素 | 問い | 失敗の形 |
|---|---|---|
| **決定** | 何を決めるのか。1文。 | 決定が複数混ざる。「〜を検討する」で終わる |
| **選択肢** | 現状維持を含む3つ以上。 | 2択。現状維持を比較から外す |
| **基準** | 何で比べるか。重みは。 | 基準が事後に都合よく増える |
| **証拠** | 各案の効果・費用・リスクの根拠。 | 数字のない断言。ベンダーの主張を証拠にする |
| **トレードオフ** | どの基準を犠牲にするか。誰が負担するか。 | 「全部よくなる」と書く |
| **推奨** | どれを、どの条件で採るか。 | 条件のない推奨 |
| **撤退条件** | 何が観測されたら戻すか。 | 「様子を見る」で終わる |

### 1.1 決定の1文

悪い例：「検索基盤について検討した結果、いくつかの選択肢があることがわかった。」
良い例：「文書検索は BM25 を主、ベクトル検索を再ランクに限定して残す。ただし日本語の表記ゆれ対応が F1 を 5 ポイント以上改善する場合に限る。」

決定は、反証可能で、範囲が限定され、日付と所有者を持つ。

---

## 2. 選択肢の作り方

- **現状維持（do nothing）を必ず1つ入れる。** 現状維持の費用を書かないと、変化の便益が過大に見える。
- 少なくとも3つ。2択は、しばしば偽の二択である。
- 各案を、同じ粒度で書く。片方だけ詳細にすると比較にならない。
- 「両方やる」「段階的にやる」も独立した案として扱う。ただし、費用と複雑性を隠さない。
- 実行不可能な案を並べて推奨を引き上げない（P03 の変種）。

### 2.1 選択肢の最小セット

| 案 | 内容 | 初期費用 | 運用費用 | 可逆性 | 主なリスク |
|---|---|---|---|---|---|
| A 現状維持 | | | | 高 | |
| B 置換 | | | | 低 | |
| C 併用 | | | | 中 | |
| D 段階移行 | | | | 中 | |

空欄は `【未確認】` と書く。空欄を埋めるために数字を作らない（R02）。

---

## 3. 基準と重み

- 基準は、決定の前に列挙する。決定の後に足さない。
- 重みは、序列でよい（must / should / could）。数値化が恣意的なら、数値にしない。
- 「必須条件（must）」を先に置く。must を満たさない案は、点数が高くても落とす。
- 基準には、少なくとも次を含める。
  - 目的への効き方（効果量、確度）
  - 費用（初期・運用・機会費用）
  - リスク（失敗時の被害、回復可能性）
  - 可逆性（戻せるか、戻す費用）
  - 分配（誰が負担し、誰が受益するか）
  - 実施能力（運用できるか、監視できるか）

### 3.1 可逆性で場合分けする

| 可逆性 | 例 | 必要な証拠の水準 |
|---|---|---|
| 容易に戻せる | 設定変更、A/B テスト | 小さく試す。結果を記録する |
| 戻すのに費用がかかる | ライブラリ移行、組織変更 | 予備調査と撤退条件。パイロット |
| 戻せない | 公開表明、データ削除、契約 | 独立レビュー、人間の承認、最悪ケース |

不可逆な判断に、可逆な判断と同じ軽さで答えてはいけない。逆も同じである。

---

## 4. 証拠の扱い（記事モードと同じ規律）

- 事実主張には出典IDを付ける（R01）。確認できなければ `【未確認】`（R02）。
- ベンダー資料・社内の成功事例は、`secondary-only` として扱う。一次データがない限り、効果の推定に使わない。
- 比較対象の条件を揃える。ベンチマークの数値を、自組織のデータ量・クエリ分布・SLA に外挿するときは、外挿であると書く。
- 効果の推定は、点ではなく区間で書く。区間がなければ「不明」と書く。
- 相反する証拠は消さない。`contradictions.md` に残す。
- 過去の類似判断があれば、その結果（成功・失敗）を証拠として使う。ただし生存者バイアスを確認する。

### 4.1 不確実性下の決定ルール

| ルール | 使うとき | 限界 |
|---|---|---|
| 期待値 | 確率と損益を粗くでも推定できる | 破滅的な結果を平均で薄める |
| 最悪ケース（maximin） | 破滅・不可逆・安全に関わる | 機会損失を無視しやすい |
| 後悔の最小化（minimax regret） | どの状態が起きるかわからない | 状態の列挙に依存する |
| 段階的コミット | 学習しながら進める | 中間状態の運用費用 |

ルールは1つに固定しない。どのルールを使ったかを書き、感度分析（前提を変えたら結論が変わるか）を示す。

## 5. 手順（Phase との対応）

### Phase 0 — 決定の固定

- 決定を1文にする。誰が決めるか、いつまでに決めるかを書く。
- 決定の種類を分類する：可逆 / 不可逆、即時 / 段階的、個人 / 組織。
- 決めない場合の帰結（現状維持の費用）を書く。

### Phase 1 — 証拠集め

- 判断に効く事実だけを集める。網羅性より、診断性（どの案を選ぶかが変わる証拠）を優先する。
- 各案について、支持する証拠と反対する証拠を1つ以上。
- 自組織の制約（予算、人員、締切、法規、既存契約）は `【未確認】` を許さず、確認する。確認できなければ決定を保留する。

### Phase 2 — 選択肢と基準

- 選択肢を3つ以上、現状維持を含めて書く。
- 基準と must 条件を先に固定する。
- 各案 × 基準の表を作る。空欄は `【未確認】`。

### Phase 2.5 — 推論の点検

- 各案の効果主張について、因果か相関かを区別する。
- 「導入した企業は成功した」は選択効果かもしれない。交絡・生存者バイアスを検討する。
- ベンチマークの外挿は、条件の差を書く。
- 反証条件：「この指標がこうなったら、この案は失敗とみなす」。

### Phase 3 — 論証と推奨

- 基準 → 評価 → 推奨 の順で組む。結論（推奨）を1文で書く。
- 最強の反対案を、その支持者の言葉で書く。
- 推奨は条件付きでよい：「X が成り立つなら A、成り立たないなら B」。
- 推奨しない案について、捨てた理由を1行で書く。

### Phase 3.5 — 規範（該当する場合）

- 誰の負担で誰が受益するか。
- 影響を受けるが決定に参加しない人（利用者、運用者、将来の保守者）を列挙する。
- 価値前提（何を優先するか）を1文で書く。

### Phase 4 — 決定メモを書く

- `assets/decision-memo.md` を埋める。記事の文体は不要。
- 1〜3頁。読み手は、決定を承認する人と、後から検証する人。
- 数字は来歴付き（R12）。決定に効かない数字は削る。

### Phase 5 — 赤チーム

- **反対者**：この決定が失敗する最も現実的な経路は何か。
- **運用者**：現場で回るか。監視・障害対応・教育は誰がやるか。
- **会計**：初期費用だけでなく、運用・移行・撤退の費用を数えたか。
- **規範**：負担が弱い立場に偏っていないか。
- プレモーテム：「1年後、この決定は失敗だった。何が起きたか」を3つ書く。

### Phase 6 — 納品

- 決定メモ、出典台帳、主張台帳、ドシエ。
- 納品メッセージは §5.2 の6点を `decision` 用に読み替える。

---

## 6. 完了条件

- 決定が1文で、所有者と日付がある。
- 選択肢が3つ以上、現状維持を含む。
- 基準と must 条件が、評価の前に固定されている。
- 各案の主要な主張に証拠IDまたは `【未確認】` がある。
- トレードオフ（何を犠牲にしたか）が明記されている。
- 撤退条件が、観測可能な指標で書かれている。
- 最強の反対案が書かれている。
- 未確認事項と、それを確認する担当・期限がある。

---

## 7. よくある失敗

| 失敗 | 兆候 | 対処 |
|---|---|---|
| 決定のすり替え | 相談が「調査します」で終わる | 決定を1文にし、期限を置く |
| 現状維持の過小評価 | 変化の便益だけを数える | 現状維持の費用を1行で書く |
| 数値の authority | ベンダー資料の数字をそのまま使う | `secondary-only` と明記。一次データを探す |
| 不可逆性の無視 | 戻せない決定を軽く扱う | §3.1 の表で分類する |
| 撤退条件の不在 | 「様子を見る」 | 指標・閾値・期限・担当を書く |
| 記事化 | 背景とまとめが膨らみ、決定が薄まる | 決定メモの型に戻す |

---

## 8. 限界

- このモードは、決定を**監査可能**にする。正しい決定を保証しない。
- 政治・組織の力学は、明示的な基準の外にある。必要なら「決定の制約条件」として書く。
- 確率と損益の推定が粗い場合、期待値の比較は精度を装う。感度分析か、順序比較に落とす。

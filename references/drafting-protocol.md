# Drafting Protocol

Phase 4 の詳細。目的は「上手に書く」ことではなく、**読者が論証を追えるように、証拠と推論を配置する**こと。

> **役割分担**：このファイルは Phase 4 の**最低線**（CEAL、グラウンディング、引用、数値、文体、AI slop）を定める。
> 読者設計、構造の選択、冒頭・見出し・リード・結末、語り、声の校正、媒体適応、推敲の5パス、読者テストは
> `references/writing-craft.md` を使う。両方を読む場合、**事実・引用・不確実性・反論**についてはこのファイルが優先し、
> 読みやすさや声はそれらを上書きしない。

---

## 1. 読者の状態を設計する

書き始める前に、読者の「現在地」と「到達点」を決める。

| 項目 | 問い |
|---|---|
| 既知 | 読者は何を知っているか。どの用語なら定義なしで通じるか。 |
| 問い | 読者は何を知りたくてこの記事を開いたか。 |
| 疑い | 読者が最初に抱く反論は何か。 |
| 関心 | 読者は何を面白いと思うか。何に疲れるか。 |
| 到達点 | 読み終えた読者は、何を言えるようになっているか。 |

**ルール**：読者の現在地を高く見積もりすぎない。専門用語は、その分野の読者にだけ通じる。一般読者向けなら、初出で1文の定義を置く。

### 1.1 節ごとの「読者の変化」

各節に、読み終えた読者の状態を書く。

- 節1を読む前：X が問題だとは思っていない。
- 節1を読んだ後：X が問題だと理解し、なぜ難しいかを知っている。
- 節2を読んだ後：主要な説明仮説を2つ知っている。
- 節3を読んだ後：証拠がどちらを支持するか、その限界を知っている。

**変化のない節は、削るか統合する。**

## 2. 段落は1つの仕事（CEAL）

### 2.1 CEAL の構造

| 要素 | 仕事 | 長さの目安 | 失敗すると |
|---|---|---|---|
| **Claim** | その段落の主張を1文で示す | 1文 | 何が言いたいかわからない |
| **Evidence** | 出典ID付きの証拠を示す | 1〜3文 | 主張が根拠なく浮く |
| **Analysis** | 証拠がなぜ主張を支えるかを説明する（Warrant） | 1〜3文 | 証拠の羅列になる |
| **Link** | 次の段落への橋、または限定条件 | 1文 | 段落が唐突に切れる |

### 2.2 例

> **Claim**：週2日の在宅勤務は、知識労働者の主観的生産性を高める可能性がある。**Evidence**：2024年の無作為化比較試験では、週2日群の自己申告生産性が対照群より4.2%高かった（n=1,200、95%信頼区間 1.1〜7.3）[S03]。**Analysis**：この差は、通勤時間の削減と集中時間の増加という2つの経路で説明できる。ただし、自己申告指標は実際の成果を過大評価する可能性がある。**Link**：したがって、この結果は「主観的生産性」の範囲にとどまり、客観的成果への一般化には追加の検証が要る。

### 2.3 段落の失敗パターン

| パターン | 症状 | 修正 |
|---|---|---|
| **証拠の羅列** | 研究A、研究B、研究C…と並ぶだけで、なぜ並べたかわからない | 各証拠の後に「だから何か」を書く |
| **主張だけ** | 「重要だ」「必要だ」が続く | 証拠とメカニズムを入れる |
| **分析なし** | 引用の後に、自分の解釈がない | Warrant を1文で書く |
| **二つの段落が混ざる** | 1段落に2つの主張 | 分割する |
| **リンクなし** | 段落が唐突に終わる | 次の段落との関係を1文で示す |
| **長すぎる** | 1段落が10文以上 | 3〜6文に分割する |
| **短すぎる** | 1文だけの段落が連続 | 統合するか、見出しにする |

## 3. 文の順序と接続

### 3.1 Given-New

文は「既知の情報 → 新情報」の順に置くと読みやすい。

- 悪い例：「4.2%という数字は、この研究の重要な発見だ。2024年のRCTが報告した。」
- 良い例：「2024年のRCTは、週2日群の生産性が4.2%高いと報告した。この差は重要だが、自己申告指標である点に注意が要る。」

### 3.2 トピックセンテンス

段落の最初の文で、その段落の主張を示す。新聞・学術論文・政策文書の多くはこの形が読みやすい。

- 例外：物語調、緊張を保つ記事では、最後に主張を置くこともある。ただし、段落の仕事が不明にならないようにする。

### 3.3 接続詞の機能

| 機能 | 日本語 | 英語 | 使いどころ |
|---|---|---|---|
| 追加 | さらに、加えて、また | moreover, furthermore | 同じ方向の証拠を積む |
| 対比 | しかし、一方で、他方 | however, by contrast | 反対証拠、別の解釈 |
| 因果 | したがって、ゆえに、その結果 | therefore, as a result | 推論の結論 |
| 譲歩 | たしかに、確かに、とはいえ | admittedly, although | 反論を一部認める |
| 例示 | たとえば、具体的には | for example | 抽象を具体化 |
| 限定 | ただし、少なくとも、この範囲では | however, at least | 結論の範囲を狭める |
| 要約 | つまり、言い換えれば | in other words | 難解な説明の後 |
| 順序 | まず、次に、最後に | first, next, finally | 手順・歴史 |

**禁止**：意味のない接続詞。「また」「さらに」を連打すると、論理関係が不明になる。接続詞を削っても意味が通るなら、削る。

### 3.4 文の長さとリズム

- 1文は40〜60字（日本語）を目安。長い文は分割する。
- 重要な主張は短い文で書く。
- 同じ長さの文が続くと単調になる。長短を混ぜる。
- 読点は息継ぎの位置。多すぎると読みにくい。
- 修飾語は被修飾語の近くに置く。

## 4. 概念のグラウンディング

### 4.1 概念の予算

読者が一度に保持できる新しい概念は、段落あたり1〜2個である。それ以上入れると、読者は前の概念を忘れる。

- 記事全体で導入する主要概念は3〜7個に絞る。
- 各概念は、初出時に定義するか、読者が知っている前提かを明示する。
- 定義は1文で。長い定義は脚注か用語集に逃がす。

### 4.2 定義の3つの方法

1. **定義**：「X とは、〜のことである。」
2. **例示**：「X とは、たとえば〜のようなものである。」
3. **対比**：「X は Y とは違い、〜である。」

**併用**が最も強い。定義＋例＋対比を1段落に収める。

### 4.3 グラウンディングの監査

各段落について問う。

- この段落で初めて出る概念は何か。
- それは定義済みか、読者の既知か。
- 定義なしで使っている専門用語はないか。
- 前の段落で導入した概念を、正しく使っているか。
- 比喩を使った場合、その比喩の限界を示したか。

### 4.4 比喩の危険

比喩は理解を助けるが、**比喩が主張を証明することはない**。

- 比喩の対応関係を明確にする。
- 対応しない部分（disanalogy）を明示する。
- 比喩を結論の根拠にしない。
- 使い古された比喩（氷山の一角、両刃の剣、諸刃の剣）は、具体性を失う。

## 5. 引用の書き方

### 5.1 直接引用を使う条件

次のいずれかに当てはまるときだけ、直接引用する。

- **文言そのものが争点**（法的定義、政策文書の表現、相手の主張）。
- **要約すると意味が変わる**（繊細なニュアンス、強い表現）。
- **証拠としての臨場感が必要**（当事者の証言）。

それ以外は、自分の言葉で要約し、出典を付ける。

### 5.2 直接引用のルール

- 原文のまま。語尾を変えない。省略は `…` で示す。
- 前後の文脈を壊さない。都合の良い部分だけ切り取らない。
- 頁・節・段落番号を付ける：`[S01: p.12]`。
- 長い引用（日本語で100字以上、英語で40語以上）は、ブロック引用か脚注に逃がす。
- 翻訳引用は「訳者による」と明記する。
- 引用符の中に引用符を入れない。入れ子は「」→『』。

### 5.3 要約（パラフレーズ）のルール

- 原文を読み、**閉じてから**自分の言葉で書く。
- 原文の語句を不必要に残さない。残すなら引用符を付ける。
- 要約が原文の主張と一致するか、読み返して確認する。
- 出典を付ける。頁まで付けるのが望ましい。
- 「〜と主張している」と、自分の解釈を混ぜない。

### 5.4 引用マーカーの位置

- 日本語：文末の句点の前に置く。「〜である [S01]。」
- 英語：文末のピリオドの前に置く。`... (S01).`
- 複数：`[S01; S04]`。
- 頁：`[S01: p.12]`。節：`[S01: §3]`。
- 主張ID：`[C03]`。読みにくくなるなら本文に残さず、`claims.csv` で対応付ける。

### 5.5 引用の失敗パターン

| パターン | 問題 | 修正 |
|---|---|---|
| **飾り引用** | 出典はあるが、主張を支えていない | 主張と証拠の対応を確認 |
| **二次引用の孫引き** | 元論文を読まずに、レビューの引用を引用 | 一次資料に遡る。無理なら `secondary-only` |
| **文脈の切り取り** | 都合の良い1文だけ引用 | 前後を読む。反対の記述も探す |
| **引用の山** | 1文に5個の出典 | 本当に必要なものだけに絞る |
| **著者の見解とデータの混同** | 論文の考察を結果として引用 | Results と Discussion を分ける |
| **撤回論文の引用** | 撤回を知らずに引用 | 撤回・訂正を確認 |
| **AI 生成の書誌** | 実在しない DOI | すべて検証する |

## 6. 数値の書き方

### 6.1 5点セット

数値を書くときは、必要に応じて次を揃える。

1. **絶対値**：42人、3.2%。
2. **相対値**：1.8倍、前年比+12%。
3. **分母**：全1,200人のうち。
4. **期間・集団**：2023年、日本の20〜30歳。
5. **不確実性**：95%信頼区間、標準誤差、幅。

例：
> 2023年の調査では、回答者1,200人のうち42人（3.5%、95%CI 2.6〜4.7）がXを経験した [S02: p.8]。

### 6.2 よくある数値の誤り

| 誤り | 例 | 修正 |
|---|---|---|
| 分母の欠落 | 「感染者が2倍に」 | 何人から何人へ |
| 絶対リスクの欠落 | 「リスクが50%増」 | 2%→3%か、20%→30%か |
| ポイントと%の混同 | 「5%から10%へ5%増」 | 5ポイント増 |
| 平均と中央値の混同 | 「平均年収が高い」 | 分布を見る |
| 名目と実質の混同 | 「賃金が上昇」 | 物価調整する |
| 期間の欠落 | 「増加している」 | いつからいつまで |
| 集団の欠落 | 「若者はXだ」 | 何歳の、どの国の |
| 丸めの過剰 | 「約100%」 | 元の数値を示す |
| 比較不能な指標 | 「A国はB国より幸福」 | 尺度・定義を揃える |
| グラフの軸操作 | 縦軸を0から切る | 誤解を招くなら注記 |

### 6.3 変化の表現

- **%**: 元の値に対する割合。「10%から12%へ20%増」。
- **ポイント**: 割合の差。「10%から12%へ2ポイント増」。
- **倍**: 「2倍」は元の値の200%。「200%増」は元の値の3倍。
- **pp**: percentage point。日本語では「ポイント」と書く。

### 6.4 グラフ・表

- グラフは、本文で言いたいことを1つに絞る。
- 軸ラベル、単位、期間、出典を必ず入れる。
- 縦軸を0から切る場合は、その理由を注記する。
- 表と本文の数字を一致させる。
- 色だけで区別しない（色覚多様性）。
- 3D グラフ、過剰な装飾を避ける。

## 7. 不確実性の言語

### 7.1 確信度の階梯

| 表現 | 意味 | 使える条件 |
|---|---|---|
| **証明する / 実証する** | 反証を許さない強い確立 | 数学的証明、または複数の独立した堅牢な RCT・自然実験の蓄積。通常の記事では避ける |
| **示す** | 強い証拠がある | デザインが強く、再現性があり、反対証拠が少ない |
| **支持する / 整合する** | 証拠が方向として一致 | 観察研究、複数の弱い証拠 |
| **示唆する** | 可能性があるが確定しない | 単一研究、探索的、メカニズム不明 |
| **可能性がある** | 排除できない | 証拠が弱い、間接的 |
| **不明 / 未確認** | 判断できない | データがない、アクセスできない |
| **ありそうにない** | 証拠が否定的 | 複数の研究が一貫して否定的 |

### 7.2 ヘッジの校正

- ヘッジを重ねない：「おそらく〜かもしれない」→「〜の可能性がある」。
- ヘッジを減らすべき場所：自分の推論の結論。読者に責任を押し付けない。
- ヘッジを増やすべき場所：因果、外挿、一般化、規範。
- 「〜と考えられる」は、誰が考えているのか不明。自分なら「私は〜と解釈する」、証拠なら「〜を示唆する」。

### 7.3 禁止表現

- 根拠なしの「明らかだ」「誰もが知るように」「常識的に」。
- 「絶対に」「必ず」「完全に」「100%」。
- 「〜に違いない」「〜以外ありえない」。
- 「画期的」「革新的」「革命的」——評価は読者に委ねる。
- 「多くの専門家は〜と言う」——誰が、何人の、どの分野か。

## 8. 文体

### 8.1 日本語

- **常体**（だ・である）を基本。指定があれば敬体。
- 一文一義。長い修飾節を避ける。
- 受動態の乱用を避ける。「〜が行われる」→「〜が行う」。
- 名詞化を避ける。「〜の実施をする」→「〜を実施する」。
- 「〜という」「〜することができる」を削る。
- 「〜において」「〜に関して」は、具体名で置き換えられるなら置き換える。
- 二重否定を避ける。
- 同じ語の繰り返しを恐れない。代名詞で曖昧にするより、名詞を繰り返す。

### 8.2 英語

- Plain English。短い文、能動態、強い動詞。
- Nominalization を避ける：`make a decision` → `decide`。
- Hedging を校正する：`may possibly suggest` → `suggests`。
- 過剰な副詞を削る：`very`, `really`, `extremely`。
- 段落の最初に topic sentence。
- 性別中立な表現。
- 分野の用語は初出で定義する。

### 8.3 見出し

- 見出しは「ラベル」ではなく「主張」にする。
  - 悪い：「背景」「考察」
  - 良い：「在宅勤務の効果は、職種によって逆転する」
- 見出しだけで論旨が追えるか確認する。
- 疑問形の見出しは、本文で答えを出す。
- 見出しの階層を飛ばさない（H2 の下に H4 を置かない）。

### 8.4 タイトルとリード

- タイトルは、問いか結論を1行で。煽らない。
- リードは、問い、なぜ重要か、結論の予告を2〜3文で。
- 「この記事では〜を論じる」というメタ宣言は、1文まで。長いと読者は本文に入れない。
- 数字を入れるなら、本文と一致させる。

## 9. AI slop チェック

AI が生成した文章に多い特徴を、意図的に排除する。

| # | 症状 | 例 | 修正 |
|---|---|---|---|
| 1 | 空の導入 | 「現代社会において、AI は急速に発展している」 | 具体的な出来事、日付、数字から始める |
| 2 | 過剰な両論併記 | 「一方で〜、他方で〜」が続く | 証拠の重みを示し、結論を出す |
| 3 | 同義反復 | 「重要なのは、大切だということだ」 | 具体的な内容を書く |
| 4 | 空虚な強調 | 「非常に重要である」「注目に値する」 | 何が、誰に、どう重要か |
| 5 | 三点列挙の乱用 | 「3つの理由がある。第一に…第二に…第三に…」 | 本当に3つ必要なときだけ |
| 6 | 過剰な箇条書き | すべてを bullet にする | 論証は段落で書く |
| 7 | まとめの繰り返し | 各節の最後に「まとめると」 | 節の最後は次への橋にする |
| 8 | 偽の深化 | 「より深く見ると」「本質は」 | 具体的なメカニズムを書く |
| 9 | 曖昧な数量 | 「多くの」「様々な」「一部の」 | 数字、範囲、事例 |
| 10 | 無内容の結論 | 「今後の展開が期待される」 | 何が、いつ、誰によって |
| 11 | 接続詞の連打 | 「また」「さらに」「加えて」 | 論理関係を明確に |
| 12 | ダッシュの多用 | 「X —— それは Y —— である」 | 文を分ける |
| 13 | 完璧なバランス | 常に長所と短所を同数並べる | 証拠に応じて重みを変える |
| 14 | 具体例の欠如 | 抽象語だけが続く | 1段落に1つは具体例 |
| 15 | メタ発言 | 「この記事では」「本稿では」の連発 | 1回まで |
| 16 | 感情の押し付け | 「驚くべきことに」「衝撃的だ」 | 事実で驚かせる |
| 17 | 過剰な一般化 | 「誰もが」「すべての人が」 | 範囲を限定する |
| 18 | 偽の対話 | 「よくある疑問は〜だろう」 | 実際の反論を書く |
| 19 | 用語の流行 | 「〜の文脈で」「〜的アプローチ」 | 具体的に書く |
| 20 | 翻訳調 | 「〜を行うことが可能である」 | 「〜できる」 |

**テスト**：同じ内容を、具体例を1つ入れて書き直せるか。書き直せないなら、内容が空である。

### 9.1 クラスタ判定と「具体性の捏造」防止

AI slop は単語1つで判定しない。同じ段落に**2つ以上の兆候**が重なったときだけ修正する。学術の hedge、ビジネスの定型、詩の反復など、ジャンルで正当な表現は残す。

- AI検出器のスコアを下げるための書き換えをしない。
- 「AIっぽい語」の禁止リストで機械的に消さない。
- 声を消して無難な文章にしない。

**具体性は証拠から来る。** 文章を具体化するために、体験談、場面、会話、数字、固有名詞を足す場合、それは資料に存在するか、ユーザーが提供した事実でなければならない。存在しない場合は `【未確認：〜が必要】` と書く。**雰囲気のための具体性は捏造である。**

### 9.2 保存チェック

推敲の前後で、次が変わっていないことを確認する。

- 事実、引用、数値、名前、日付、URL、頁。
- `【未確認】`、hedge（可能性がある、〜の範囲では）、限定条件。
- 引用マーカーと出典の対応。
- 見出しと本文の約束。

読みやすくするために、これらを削らない。削る必要があるなら、理由を `revision-log.md` に残す。

## 10. 節タイプ別の書き方

### 10.1 序論

- 問いを提示する。読者が「自分の問題だ」と思う形で。
- なぜ今か。何が未解決か。
- 結論を予告する（thesis-first の場合）。
- ロードマップは短く。3文以上は不要。
- **禁止**：人類の歴史から始める。AI の定義から始める。誰も聞いていない前提を長々と説明する。

### 10.2 背景

- 読者が本文を理解するための最小限の情報だけ。
- 定義、制度、時系列、主要な論争。
- 「先行研究」を論文ごとに紹介しない。テーマで統合する。
- 背景だけで1節を使うなら、その節に仕事があるか確認する。

### 10.3 証拠節

1. 主張（この節で示すこと）。
2. 研究のデザイン（誰を、いつ、どう調べたか）。
3. 主要な結果（効果量、信頼区間、分母）。
4. 解釈（Warrant）。
5. 限界（何を言えないか）。
6. 次の証拠への橋。

**禁止**：Abstract のコピー。結果と考察の混同。p値だけの報告。

### 10.4 反論節

1. 相手の最強の主張を、相手の言葉で。
2. 相手の根拠を公正に示す。
3. 譲れる点を譲る。
4. 譲れない点を、証拠で反駁する。
5. 結論が変わるなら、変える。

**禁止**：弱い版本だけを扱う。相手の人格を攻撃する。「意見が分かれている」で終わる。

### 10.5 限界節

- 何がわかっていないか。
- どの証拠が弱いか。
- どの集団・文脈に一般化できないか。
- どんな観察があれば結論が変わるか。
- 利害関係、資金、立場。

**禁止**：「限界はあるが、それでも重要だ」で終わる。限界を書くだけで、結論への影響を書かない。

### 10.6 結論

- 問いに1文で答える。
- 条件と範囲を再確認する。
- 含意（誰にとって、何が変わるか）。
- 未解決の問い。
- **禁止**：本文の要約を繰り返すだけ。「今後の研究が待たれる」で終わる。新しい主張を追加する。

## 11. 推敲

### 11.1 逆アウトライン

書き終えたら、各段落の主張を1文で抜き出す。並べて読む。

- 論証の順序が通っているか。
- 同じ主張が繰り返されていないか。
- 抜けている論証はないか。
- 段落の仕事が不明なものはないか。

### 11.2 音読

- 詰まる場所は、文が長いか、論理が飛んでいる。
- 同じ語が続く場所は、リズムが悪い。
- 意味が取れない文は、書き直す。

### 11.3 削る

- 10%削るつもりで読む。
- なくても意味が通る文、段落、節を削る。
- 形容詞・副詞を削る。
- メタ発言を削る。
- 繰り返しを削る。
- ただし、証拠、限定条件、反論は削らない。

### 11.4 最終確認

- [ ] 各段落に Claim があるか。
- [ ] 各 Claim に Evidence があるか（事実主張の場合）。
- [ ] Evidence の後に Analysis があるか。
- [ ] 段落間の Link があるか。
- [ ] 初出の概念は定義されているか。
- [ ] 引用は主張を本当に支えているか。
- [ ] 数値の分母・単位・期間・集団は揃っているか。
- [ ] 不確実性の言語は、証拠の強さと一致しているか。
- [ ] 見出し・リード・本文・結末の約束が一致しているか。
- [ ] 各節で読者の状態が変わるか。
- [ ] 意識的に使った技法は3〜5個に絞られているか。
- [ ] 旧情報→新情報、行為者→動詞になっているか。
- [ ] 声は媒体・読者・文体サンプルに合っているか。
- [ ] 構造→段落→文→声→保存の順で推敲したか。
- [ ] 推敲で事実・引用・数値・hedge・限定条件が変わっていないか。
- [ ] AI slop はクラスタで確認したか。単語1つで判定していないか。
- [ ] 音読して詰まらないか。
- [ ] 10%削れるか。削ったか。
